CHILLY WILLY — BULBASAUR HALLOWEEN v1.0.1 (CORREGIDO)
=====================================================
Código fuente para Fabric 1.21.1, Java 21, GeckoLib 4.7.3, Pokeblocks 1.4.0.
El modelo 3D y la textura personalizados fueron conservados SIN CAMBIOS.

CAMBIOS EN 1.0.1
- Se quitó GeckoLib.initialize(): no existe en GeckoLib 4.7.3.
- Se corrigió el constructor de GeoBlockRenderer: super(new HalloweenBulbasaurModel()).
- Las 2 advertencias de métodos deprecated se suprimen sin modificar las firmas ya compatibles.
- Se actualizó la versión a 1.0.1 y el nombre del artefacto en GitHub Actions.

PARA ACTUALIZAR TU REPOSITORIO EXISTENTE
1. Abrí tu repositorio de GitHub `Chilly-Bulbasaur`.
2. Reemplazá el contenido de los archivos del repositorio por los del ZIP (CONSERVANDO las carpetas y el directorio oculto .github).
3. Hacé Commit changes.
4. Entrá a Actions > Compilar Bulbasaur Halloween.
5. Si no se inicia automáticamente, pulsá Run workflow.
6. Si sale verde, abrí el run > Artifacts y descargá el ZIP del build.
7. Extraé el archivo `Chilly-Bulbasaur-Halloween-1.0.1.jar` (no usar -sources.jar).
8. Instalá ese JAR en servidor y clientes con Minecraft 1.21.1, Fabric, Fabric API, GeckoLib y Pokeblocks.
9. Probalo PRIMERO en un mundo de pruebas antes de instalarlo en el servidor principal.

COMANDO PLANIFICADO (cuando el mod esté instalado):
/give @p chilly_halloween:bulbasaur_halloween 1

FUNCIONES PLANIFICADAS
- ID único de bloque + item: chilly_halloween:bulbasaur_halloween
- Sin receta, solo OP por comando.
- Se puede colocar y recuperar al romperlo.
- No sustituye el Bulbasaur normal de Pokeblocks.

NOTA DE VALIDACIÓN
Se compararon los archivos y se comprobó su estructura y JSON. Esta máquina no puede
compilar el mod con Gradle ni iniciar Minecraft para probarlo. Las correcciones de Java
abordan exactamente los dos errores que aparecen en el log enviado. Si Actions muestra
otro error, será necesario revisar el nuevo log.
